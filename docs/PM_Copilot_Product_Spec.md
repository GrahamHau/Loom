# Loom — 产品设计规格文档

> **命名说明**：当前产品名统一为 Loom。文档、代码或设计导出中残留的 PM Copilot / pm-copilot 都是旧名，除非专门做运行时迁移，否则只当作历史标识处理。

> **产品定位**：产品经理的个人情报中台。解决信息分散、无法结构化、AI 无法调用的问题。
>
> **核心用户**：单个产品经理（架构预留多用户扩展）
>
> **部署环境**：VPS（2C4G/70GB）→ 后续迁移公司服务器
>
> **技术约束**：Vibecoding + Codex 实现，前端飞书风格，后端可接入自定义大模型

---

## 一、系统架构

### 1.1 模块总览

```
┌─────────────────────────────────────────────────────┐
│                       Loom                          │
├────────────┬────────────┬──────────┬─────────────────┤
│   News     │  竞品库     │ 需求管理  │   市场调研       │
│  (信息入口) │ (数据沉淀)  │ (数据沉淀)│  (分析输出)      │
├────────────┴────────────┴──────────┴─────────────────┤
│                    AI 中间层                          │
│  筛选 / 翻译 / 打标 / 摘要 / 匹配 / 去重              │
├─────────────────────────────────────────────────────┤
│                   数据存储层                           │
│              SQLite (source of truth)                │
├─────────────────────────────────────────────────────┤
│                   同步层                              │
│           飞书多维表格（下游同步目标）                    │
└─────────────────────────────────────────────────────┘
```

### 1.2 模块关系

- **News** 和 **竞品库** 是两条**独立的信息管道**，不是上下游关系
- **News** 解决 FOMO（怕错过行业动态）
- **竞品库** 解决竞品信息分散在不同平台的问题
- **需求管理** 解决团队分享散落在群聊中无法追溯的问题
- **市场调研** 是分析层，从竞品库和需求管理中拉取结构化数据，做 AI 匹配分析
- 所有模块数据均可**单向同步到飞书多维表格**

### 1.3 技术栈建议

| 层 | 技术选型 | 理由 |
|---|---------|------|
| 前端 | React + Tailwind CSS | Codex 生态成熟，飞书风格容易复刻 |
| 后端 | Node.js (Express/Fastify) | 与前端同语言，Codex 友好 |
| 数据库 | SQLite (via better-sqlite3) | 单人使用，零运维，文件级备份 |
| 采集 | Playwright (headless Chromium) | 应对反爬，2C4G 够用但需控制并发（同时最多 1 个实例） |
| RSS | rss-parser (npm) | 轻量 RSS 解析 |
| AI 中间层 | 可配置 LLM API（OpenAI 兼容格式） | 设置页面可切换模型（MiniMax / DeepSeek / Claude 等） |
| 飞书同步 | 飞书开放平台 API（多维表格） | 官方 REST API，token 鉴权 |
| 部署 | Docker Compose（Nginx + Node + Playwright） | 一键部署，后续迁移方便 |

### 1.4 多用户扩展设计（预留但不实现）

- 所有数据表包含 `user_id` 字段
- API 路由预留 JWT 鉴权中间件位置（当前写死为默认用户）
- 登录页面做出来（展示用），但当前只有一个账号
- 前端不硬编码用户身份

## 三、News 模块

### 3.1 功能定位

解决产品经理的 FOMO 问题。通过 RSS 和公开源定向采集行业信息，AI 自动筛选和翻译，以卡片+时间轴形式呈现。

### 3.2 数据源管理

用户可在设置中添加 RSS 源，包括：
- YouTube 频道 RSS
- 竞品官网 RSS / Blog
- 行业媒体 RSS
- 自定义 URL

每个源包含字段：
| 字段 | 类型 | 说明 |
|------|------|------|
| id | UUID | 主键 |
| user_id | UUID | 预留多用户 |
| name | string | 源名称（如"DJI Official Blog"） |
| url | string | RSS URL |
| type | enum | rss / webpage |
| fetch_interval | int | 采集间隔（分钟），默认 60 |
| is_active | boolean | 是否启用 |
| created_at | datetime | 创建时间 |

### 3.3 AI 筛选规则

RSS 进来的原始内容，经过 AI 中间层做两件事：

1. **分类判断**（保留 or 丢弃）
   - ✅ 保留：新品发布、行业趋势
   - ❌ 丢弃：招聘、企业社会责任、无关内容
2. **翻译**：非中文内容自动翻译为中文，保留原文

AI Prompt 模板（低智能模型可用）：
```
你是一个信息筛选助手。请判断以下内容是否属于以下两类之一：
1. 新品发布：某品牌/公司发布了新产品或新SKU
2. 行业趋势：技术方向变化、市场报告、消费趋势

如果属于其中一类，返回 JSON：{"keep": true, "type": "新品发布"|"行业趋势", "title_zh": "中文标题", "summary_zh": "50字以内中文摘要"}
如果不属于，返回：{"keep": false}

内容：{content}
```

### 3.4 News 数据表

| 字段 | 类型 | 说明 |
|------|------|------|
| id | UUID | 主键 |
| user_id | UUID | 预留 |
| source_id | UUID | 外键，关联数据源 |
| original_title | string | 原始标题 |
| original_url | string | 原始链接 |
| original_content | text | 原始正文（截取前 2000 字） |
| title_zh | string | AI 翻译后的中文标题 |
| summary_zh | string | AI 摘要（50 字以内） |
| type | enum | "新品发布" / "行业趋势" |
| thumbnail_url | string | 首图 URL（从 RSS 提取） |
| is_read | boolean | 是否已读 |
| is_starred | boolean | 是否收藏 |
| published_at | datetime | 原始发布时间 |
| created_at | datetime | 入库时间 |

## 四、竞品库模块

### 4.1 功能定位

聚合竞品收集系统。用户粘贴链接自动采集，AI 结构化处理，支持多平台信息聚合在同一条记录下。

### 4.2 竞品数据表

| 字段 | 类型 | 说明 |
|------|------|------|
| id | UUID | 主键 |
| user_id | UUID | 预留 |
| name | string | 商品名称 |
| category | string | 产品品类（公司已有品类体系） |
| tags | string[] | 自定义标签 |
| status | enum | "新录入" / "跟踪中" / "已归档" |
| thumbnail_url | string | 首图 URL（自动采集或用户上传） |
| thumbnail_emoji | string | 无首图时的 emoji 替代 |
| ai_summary | text | AI 生成的竞品摘要 |
| selling_points | string[] | 核心卖点标签 |
| negative_keywords | string[] | 差评关键词 |
| notes | text | 用户自由备注 |
| created_at | datetime | 录入时间 |
| updated_at | datetime | 最后更新 |
| synced_at | datetime | 最后同步飞书时间 |

### 4.3 竞品平台信息表（一对多）

每条竞品可挂载 1-3 个平台信息：

| 字段 | 类型 | 说明 |
|------|------|------|
| id | UUID | 主键 |
| product_id | UUID | 外键，关联竞品 |
| platform | enum | "amazon" / "taobao" / "jd" / "xiaohongshu" / "kickstarter" |
| url | string | 商品链接 |
| sku_id | string | 平台商品 ID（ASIN / 淘宝 ID 等） |
| price | string | 售价（带币种符号） |
| cost_estimate | string | 参考成本（手动填写） |
| rating | float | 评分 |
| review_count | int | 评论数 |
| monthly_sales | string | 月销估算 |
| fetched_at | datetime | 采集时间 |

### 4.4 采集流程

```
用户粘贴链接
    ↓
前端判断平台（根据 URL 域名）
    ↓
后端调用 Playwright 打开页面
    ↓
提取页面 HTML → 发送给 AI 中间层
    ↓
AI 返回结构化 JSON：{name, price, rating, review_count, monthly_sales, image_url, selling_points}
    ↓
前端显示"解析成功"预览 → 用户确认/修改 → 保存
```

**Playwright 约束：**
- 同时最多 1 个浏览器实例（2C4G 限制）
- 单次采集超时 30 秒
- 首图采集：亚马逊首图可能被反爬拦截，采集失败时前端提示用户手动上传，或使用 emoji 替代

**AI 采集 Prompt 模板：**
```
从以下网页内容中提取商品信息，返回 JSON 格式：
{
  "name": "商品全称",
  "price": "售价（含币种符号）",
  "rating": 评分数字,
  "review_count": 评论数,
  "monthly_sales": "月销估算",
  "image_url": "首图URL",
  "selling_points": ["卖点1", "卖点2", ...],
  "negative_keywords": ["差评关键词1", ...]
}
如果某字段无法提取，值设为 null。

网页内容：{html_content}
```

## 五、需求管理模块

### 5.1 功能定位

集中收集产品需求和灵感。来源包括小红书、Kickstarter、YouTube、Instagram 等社媒。用户粘贴链接录入，AI 自动结构化打标，后续供 Agent 调用做市场分析。

### 5.2 数据结构

| 字段 | 类型 | 说明 |
|------|------|------|
| id | UUID | 主键 |
| user_id | UUID | 预留 |
| title | string | 需求/灵感标题 |
| source_url | string | 来源链接 |
| source_platform | enum | "xiaohongshu" / "kickstarter" / "youtube" / "instagram" / "other" |
| thumbnail_url | string | 首图（从链接采集） |
| original_content | text | 原文内容 |
| summary | text | AI 摘要（短内容直接用原文，长内容 AI 总结） |
| tags_category | string[] | 产品品类标签（公司已有体系） |
| tags_scenario | string[] | 使用场景标签（从预设列表匹配） |
| tags_painpoint | string[] | 用户痛点标签（从预设列表匹配） |
| tags_innovation | string[] | 创新类型标签（从预设列表匹配） |
| tags_custom | string[] | 用户自定义标签 |
| import_method | enum | "manual" / "agent_auto" |
| is_confirmed | boolean | 是否已确认（Agent 导入默认 true，手动导入需确认） |
| created_at | datetime | 录入时间 |
| updated_at | datetime | 更新时间 |

### 5.3 标签体系

#### 使用场景（12 个，AI 多选）
| 标签 | 说明 |
|------|------|
| Vlog / 自拍 | 手持自拍、口播记录 |
| 直播 / 带货 | 直播间、带货场景 |
| 短视频创作 | 抖音/YouTube Shorts 等平台内容 |
| 户外旅拍 | 旅行、户外风光拍摄 |
| 室内棚拍 | 影棚、室内打光环境 |
| 桌面俯拍 | 开箱、美食、手工等桌面内容 |
| 会议 / 活动记录 | 企业会议、活动现场 |
| 运动 / 极限拍摄 | 骑行、滑雪、潜水等运动场景 |
| 产品摄影 | 电商图、白底图、产品展示 |
| 延时 / 慢动作 | 延时摄影、高帧率慢动作 |
| 街拍 / 纪实 | 街头抓拍、纪实摄影 |
| 教育 / 网课 | 在线教学、录屏分享 |

#### 用户痛点（15 个，AI 多选）
| 标签 |
|------|
| 携带不便 / 太重 |
| 续航不足 |
| 操作复杂 / 学习成本高 |

| 做工质感差 |

#### 创新类型（6 个，AI 单选）
| 标签 | 说明 |
|------|------|
| 技术创新 | 新传感器、新算法、新材料 |
| 使用方式创新 | 新的操控/交互方式 |

| 场景拓展 | 把产品带入新的使用场景 |
| 生态整合 | 多设备联动、APP 控制、平台打通 |
| 性价比创新 | 同等性能更低价格 |

### 5.4 AI 打标 Prompt 模板


## 六、市场调研模块

### 6.1 功能定位

产品经理输入一个产品想法，系统从竞品库和需求管理中匹配关联数据，AI 生成分析报告。

### 6.2 数据结构

| 字段 | 类型 | 说明 |
|------|------|------|
| id | UUID | 主键 |
| user_id | UUID | 预留 |
| title | string | 调研项目名称 |
| description | text | 产品想法描述 |
| matched_products | UUID[] | 关联的竞品 ID 列表 |
| matched_demands | UUID[] | 关联的需求 ID 列表 |
| ai_analysis | text | AI 生成的分析报告（Markdown） |
| ai_confidence | float | AI 置信度（0-1） |
| status | enum | "草稿" / "分析中" / "已完成" |
| created_at | datetime | 创建时间 |
| updated_at | datetime | 更新时间 |

### 6.3 匹配逻辑

```
用户输入产品想法
    ↓
AI 提取关键信息：品类、目标场景、目标痛点
    ↓
从竞品库中按品类 + 标签匹配相关竞品
从需求管理中按场景 + 痛点标签匹配相关需求
    ↓
将匹配结果 + 用户描述一起发送给 AI
    ↓
AI 生成分析报告，包含：
  - 竞品格局总结（引用具体竞品数据）
  - 需求验证（引用具体需求条目）
  - 差异化机会点
  - 定价建议区间
  - 风险提示
每个结论标注置信度和数据来源
```

### 8.2 AI 中间层接口

所有 AI 调用统一走一个内部服务：

```javascript
// ai-service.js
async function callLLM({ system, user, responseFormat = "json" }) {
  const settings = await getSettings();
  const response = await fetch(settings.llm_api_url, {
    method: "POST",
    headers: {
      "Content-Type": "application/json",
      "Authorization": `Bearer ${settings.llm_api_key}`
    },
    body: JSON.stringify({
      model: settings.llm_model,
      messages: [
        { role: "system", content: system },
        { role: "user", content: user }
      ],
      response_format: responseFormat === "json" ? { type: "json_object" } : undefined
    })
  });
  return response.json();
}
```
