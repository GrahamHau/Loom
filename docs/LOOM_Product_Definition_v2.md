# LOOM 产品定义说明 v2.0

版本：2026-05-11  
替代旧版：PM Copilot 简版产品说明

## 1. 产品定位

LOOM 是一个个人情报工作台，把日常浏览中散落的信号编织成可调用的决策资产。

它的用户不限于产品经理：产品经理用它管理竞品和需求，销售用它积累客户洞察，决策层用它做立项判断。

它要解决五个真实工作场景：

- 行业信息分散，重要动态容易错过。
- 竞品信息散落在亚马逊、淘宝、京东、小红书、Kickstarter，无法横向比较。
- 灵感和案例散在链接、社媒、聊天里，回头找不到。
- 做市场调研时，过去看过的东西无法被系统调用。
- AI 能读内容，但缺乏整理好的本地结构化数据。

本质上 LOOM 是一条管道：

```text
采集 → 结构化 → 沉淀 → 分析 / 生成
```

## 2. 产品独特性

市面上有三类相邻产品：爬虫工具、笔记工具、知识库。

LOOM 与它们的本质区别是一句话：

> 让人成为信息的过滤器，让 AI 成为整理者。

爬虫拿广度但拿不到判断。笔记工具记得下但找不回，更不能被 AI 调用。知识库需要大量手动整理。

LOOM 的差异是：用户在自然浏览过程中沉淀带判断的高质量样本。这种样本的密度，外部任何数据源都无法复制。

## 3. 模块结构

LOOM 由五个模块组成，分两层加一个支撑层。

第一层：采集与沉淀

- **Stream · 资讯流**：外部行业动态入口。
- **Lens · 竞品库**：竞品产品档案。
- **Spark · 灵感库**：需求与灵感素材池。

第二层：分析与生成

- **Weave · 调研工坊**：基于沉淀数据做分析与组合创新。

支撑层

- **Settings · 系统设置**：数据源、AI、同步、标签的统一配置。

底层数据以 SQLite 为主，飞书多维表格是下游同步目标，不是主数据源。

中间有统一的 AI 中间层，承担：筛选、摘要、翻译、打标、结构化提取、相似度匹配、组合生成。

## 4. 模块定义

### 4.1 Stream · 资讯流

模块本质：行业雷达。从 RSS 和公开网页源中过滤出真正与产品决策相关的信号。

真实问题：直接订阅行业源会被招聘、促销、游记、教程等噪声淹没。LOOM 用 AI 做分类筛选，只保留新品发布和行业趋势两类。

核心动作：

- 定时拉取 RSS / 公开页面。
- AI 判断保留 / 丢弃。
- 翻译为中文，生成 50 字以内摘要。
- 按时间轴展示，支持收藏、跳转原文。

它不做：

- 不做新闻阅读器。
- 不做内容社区。
- 不做摘要订阅服务。

核心价值：把 100 条原始信息过滤为 10 条可决策信息。

### 4.2 Lens · 竞品库

模块本质：竞品的标准化产品档案。把分散在各平台的商品页面变成可横向比较的统一数据结构。

真实问题：收藏夹里有 Amazon、淘宝、京东和截图，但无法快速回答关键问题。LOOM 把每条竞品的关键字段标准化，同一个竞品的多平台数据挂在同一条记录下。

核心动作：

- 粘贴链接 → AI 解析页面 → 自动填充字段。
- 同一竞品可挂载多个平台信息。
- 维护卖点标签、差评关键词、AI 摘要。
- 支持飞书多维表格单向同步。

它不做：

- 不做电商比价工具。
- 不做商品收藏夹。
- 不做评论分析平台。

核心价值：把竞品从“看过”变成“可分析”。

### 4.3 Spark · 灵感库

模块本质：外部产品灵感的结构化素材池。沉淀从小红书、Kickstarter、YouTube、Instagram 等渠道捕获的需求信号。

真实问题：看到一条有意思的笔记或案例，几个月后做立项却找不到。Spark 让“这条值得记下来”的判断瞬间固化为可检索资产。

核心动作：

- 粘贴链接 → 提取标题、正文、首图。
- AI 自动打三维度标签：使用场景、用户痛点、创新类型。
- 用户补充一句备注：为什么我觉得它有意思。
- 可关联到具体竞品或调研项目。

它不做：

- 不做工单系统。
- 不做需求文档工具。
- 不做团队任务管理。

核心价值：把“灵光一现”变成“可调用的判断样本”。

### 4.4 Weave · 调研工坊

模块本质：LOOM 的分析与生成引擎。调用 Lens、Spark、Stream 的沉淀数据，做两件事：验证想法和生成想法。

模式 A：分析模式

用户输入一个产品想法，Weave 从 Lens 召回相关竞品，从 Spark 召回相关需求，从 Stream 召回相关趋势，AI 生成结构化分析报告。每条结论标注置信度和数据来源。

报告包含：

- 竞品格局。
- 需求验证。
- 差异化机会。
- 定价建议。
- 风险提示。

模式 B：生成模式

用户没有具体想法，只有方向。选择目标用户场景和目标痛点后，AI 从 Lens 的 feature 池中做排列组合，输出 N 个组合产品概念卡片。

每张卡片包含：

- feature 组合。
- 解决的痛点闭环。
- 相似竞品参考。
- 风险标注。

用户可调节“创新距离”：保守（同品类组合）到激进（跨行业组合）。

它不做：

- 不做泛泛的市场分析报告。
- 不替代人决策。
- 不脱离数据生成。

核心价值：让沉淀的数据真正用于决策，而不是停留在“收集了很多信息”。

### 4.5 Settings · 系统设置

模块本质：LOOM 的配置中台。让采集、AI 处理、同步逻辑、标签体系可配置。

核心功能：

- Stream 数据源管理。
- AI 模型配置。
- 飞书同步配置。
- 标签体系编辑。
- 账号管理。

## 5. 全局能力

登录：当前单用户登录，UI 完整。后续预留多用户扩展，数据表带 `user_id` 字段，API 预留 JWT 鉴权中间件位置。

全局搜索：跨模块统一搜索 Stream、Lens、Spark、Weave。一个搜索框，所有沉淀的数据都能被找到。

浏览器插件：`LOOM Web Clipper` 是浏览器侧边栏采集入口，用于把当前页面保存到 Lens 或 Spark。

## 6. 数据流总览

```text
外部世界
   │
   ├─ RSS / 网页 ──────→ Stream（AI 筛选）
   ├─ 商品链接 ────────→ Lens（AI 结构化）
   └─ 社媒链接 ────────→ Spark（AI 打标）
                              │
                              ▼
                         SQLite 主数据库
                              │
                    ┌─────────┼─────────┐
                    ▼         ▼         ▼
                 全局搜索  Weave 分析  Weave 生成
                              │         │
                              ▼         ▼
                         决策报告   产品概念
                              │
                              ▼
                         飞书多维表格（单向同步）
```

## 7. MVP 边界

已落地的真功能：

- 单用户登录与本地持久化。
- Stream 采集与 AI 筛选。
- Lens 新增 / 编辑 / 多平台挂载。
- Spark 新增 / 编辑 / 三维度打标。
- Weave 分析模式。
- 飞书单向同步。
- 统一 LLM 接口配置。

当前不做：

- 多人协作。
- 自动化采集平台。
- BI 系统。
- 通用知识库。
- Weave 生成模式。

v1.5 计划新增：

- Weave 生成模式。
- LOOM Web Clipper 增强。
- Spark 评论区按需采集。

## 8. 设计语言

整体气质：

- 专业、克制、信息密度高。
- 接近飞书 / Linear / Notion 的工作台体验。
- 不是消费产品，不是社区，不是花哨 dashboard。

模块命名：

- 页面和导航采用双语模块名。
- 英文主名作为模块品牌：Stream / Lens / Spark / Weave / Settings。
- 中文说明低对比辅助：资讯流 / 竞品库 / 灵感库 / 调研工坊 / 系统设置。

色彩：

- 主色 `#1F6EEB`。
- 背景 `#F5F6F8`。
- 表面 `#FFFFFF`。
- 标签和状态使用克制的专属配色。

布局：

- 左侧主导航约 200px。
- 主内容区承载列表、表格和工作流。
- 右侧详情面板按需展开。

字体：

- 中文 PingFang SC。
- 英文 SF Pro / system sans-serif。

## 9. 给 Claude / Codex 的理解重点

第一，这是一个单用户工具型产品。核心不是社交，不是协作，是个人情报管理。

第二，五个模块不是平级功能堆砌，而是分层架构：

- 采集层：Stream。
- 沉淀层：Lens、Spark。
- 分析与生成层：Weave。
- 支撑层：Settings。

第三，AI 不是装饰，是骨架。Stream 用于筛选，Lens 用于结构化，Spark 用于打标，Weave 用于召回和组合，Settings 让 AI 可配置。

第四，UI 要专业克制。不要做消费产品的视觉风格，对标飞书 / Linear。

第五，产品哲学的一句话：让人成为信息的过滤器，让 AI 成为整理者。所有设计决策都应回溯检验是否强化人的判断价值，是否让 AI 承担机械整理工作。

## 10. 一句话总结

LOOM 是一个个人情报工作台，把日常浏览中散落的信号编织成可调用的决策资产，并在此基础上协助你做出更好的产品决策。

再压缩一层：

> LOOM 让浏览变成沉淀，让判断变成资产，让 AI 帮你创造。
